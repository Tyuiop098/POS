# POS Mart — ระบบแคชเชียร์แบบร้านสะดวกซื้อ

เว็บแอปสำหรับทำแคชเชียร์เอง: ใช้ **มือถือสแกนบาร์โค้ด** ส่งข้อมูลแบบเรียลไทม์ไปที่
**หน้าจอคอมพิวเตอร์** (แสดงชื่อสินค้า ราคา ยอดรวม แบบพนักงานเซเว่น) โดยไม่ต้องรันเซิร์ฟเวอร์เอง
(ใช้ Firebase Realtime Database ฟรี เป็นตัวกลาง)

## ไฟล์ในโปรเจกต์
```
pos-system/
├── index.html      หน้าตั้งค่า (Firebase config + รหัสร้าน + เลือกอุปกรณ์)
├── cashier.html     หน้าจอแคชเชียร์ (เปิดบนคอม)
├── scanner.html     หน้าสแกนบาร์โค้ด (เปิดบนมือถือ)
├── css/style.css
├── js/app.js        ฟังก์ชันกลาง (Firebase, lookup, cart)
├── js/cashier.js
└── js/scanner.js
```

## วิธีตั้งค่า Firebase (ทำครั้งเดียว ใช้ฟรี)

1. ไปที่ https://console.firebase.google.com → **Add project** → ตั้งชื่อโปรเจกต์อะไรก็ได้
2. เมนูซ้าย → **Build → Realtime Database** → **Create Database** → เลือก location ใดก็ได้ →
   เลือกโหมด **Start in test mode** (เพื่อทดสอบก่อน ค่อยตั้งกฎความปลอดภัยทีหลัง)
3. เมนูซ้าย → ⚙️ **Project settings** → เลื่อนลงไปที่ **Your apps** → กด **</>** (Web app) →
   ตั้งชื่อ nickname อะไรก็ได้ → **Register app**
4. จะได้ก้อนโค้ดหน้าตาแบบนี้ — คัดลอกเฉพาะก้อน `firebaseConfig` ทั้งหมด:
   ```js
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "xxx.firebaseapp.com",
     databaseURL: "https://xxx-default-rtdb.asia-southeast1.firebasedatabase.app",
     projectId: "xxx",
     storageBucket: "xxx.appspot.com",
     messagingSenderId: "...",
     appId: "..."
   };
   ```
5. เปิดเว็บ POS Mart (index.html) → วางก้อนนี้ทั้งหมดในช่อง "วางค่า firebaseConfig" →
   ตั้งรหัสร้าน (เช่น `1234`) → เลือกว่าเครื่องนี้เป็นแคชเชียร์หรือมือถือสแกน → กดเริ่มใช้งาน
6. ทำซ้ำขั้นตอนที่ 5 บนอีกเครื่องหนึ่ง โดยใช้ **firebaseConfig และรหัสร้านชุดเดียวกัน**
   แต่เลือกบทบาทอีกฝั่ง (ถ้าคอมเลือก "เครื่องแคชเชียร์" มือถือก็เลือก "มือถือสแกน")

> ทั้งสองเครื่องไม่จำเป็นต้องอยู่ Wi-Fi เดียวกัน เพราะสื่อสารผ่านอินเทอร์เน็ต (Firebase)
> ใช้ได้แม้มือถือใช้เน็ตมือถือ คอมใช้ Wi-Fi คนละวง

### ตั้งกฎความปลอดภัยเบื้องต้น (แนะนำ ไม่บังคับ)
โหมดทดสอบของ Firebase จะเปิดให้ใครก็อ่าน/เขียนข้อมูลได้ภายใน 30 วัน หลังจากนั้นจะถูกปิดอัตโนมัติ
ถ้าจะใช้งานจริงต่อเนื่อง ให้ไปที่ Realtime Database → กฎ (Rules) แล้วตั้งเป็น:
```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```
(หมายเหตุ: กฎนี้ยังเปิดกว้าง เหมาะกับใช้ทดสอบ/ใช้ในวงจำกัด ถ้าต้องการความปลอดภัยสูงขึ้นควรเพิ่มระบบ
ยืนยันตัวตน (Firebase Auth) — แจ้งได้หากต้องการให้ช่วยตั้งค่าเพิ่มเติม)

## วิธีนำขึ้น GitHub Pages (ฟรี)

1. สร้าง repository ใหม่บน GitHub เช่น `pos-mart`
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์ `pos-system/` ขึ้น repo (ลากไฟล์วางในหน้าเว็บ GitHub ได้เลย
   หรือใช้คำสั่ง `git add . && git commit -m "init" && git push`)
3. ไปที่ repo → **Settings → Pages** → Source เลือก **branch: main / folder: root** → Save
4. รอ 1-2 นาที จะได้ลิงก์เช่น `https://ยูสเซอร์เนม.github.io/pos-mart/`
5. เปิดลิงก์นี้บนคอม (ตั้งค่าเป็นแคชเชียร์) และเปิดลิงก์เดียวกันบนมือถือ (ตั้งค่าเป็นสแกน)

> มือถือต้องเปิดผ่าน **https** (GitHub Pages เป็น https อยู่แล้ว) กล้องบนเว็บถึงจะทำงานได้

## วิธีใช้งาน

- **มือถือ:** เปิดกล้อง → ยิงบาร์โค้ดสินค้า → ระบบจะ:
  1. เช็คว่าเคยบันทึกสินค้านี้ไว้ไหม (มีชื่อ+ราคาที่ตั้งเองก่อนหน้า) → ถ้ามี เพิ่มลงตะกร้าเลย
  2. ถ้าไม่เคยมี จะลองดึง **ชื่อสินค้า** จากฐานข้อมูลบาร์โค้ดสาธารณะ (Open Food Facts, ฟรี ไม่ต้องขอ key)
  3. ไม่ว่าจะดึงชื่อได้หรือไม่ได้ ระบบจะถามราคา (และชื่อ ถ้าไม่พบ) แล้ว **บันทึกไว้ถาวร**
     ครั้งต่อไปสแกนบาร์โค้ดเดิม จะขึ้นชื่อ+ราคาให้อัตโนมัติทันที
- **คอม (แคชเชียร์):** ตะกร้าจะอัปเดตแบบเรียลไทม์ทุกครั้งที่มือถือสแกน มีปุ่ม +/- ปรับจำนวน
  ลบรายการ พิมพ์บาร์โค้ดเองได้ถ้าไม่มีมือถือ กด **ชำระเงิน** เพื่อบันทึกยอดขายและล้างตะกร้า
- แท็บ **สินค้า**: ดู/แก้ไข/ลบ รายการสินค้าที่บันทึกไว้ทั้งหมด (เหมือนฐานข้อมูลสินค้าในร้าน)
- แท็บ **ยอดขาย**: ดูประวัติการขายย้อนหลัง

## ข้อจำกัด (ควรรู้ไว้)

- ฐานข้อมูลบาร์โค้ดสาธารณะ (Open Food Facts) เน้นสินค้าประเภทอาหาร/เครื่องดื่มจากทั่วโลก
  สินค้าไทยหรือของร้านสะดวกซื้อบางชนิดอาจไม่มีในฐานข้อมูล — กรณีนี้ระบบจะให้กรอกชื่อเองครั้งแรก
  แล้วจดจำไว้ใช้ในครั้งถัดไปอัตโนมัติ ไม่ต้องพิมพ์ซ้ำ
- ราคาสินค้าเป็นข้อมูลเฉพาะร้านของคุณเสมอ (ไม่มีฐานข้อมูลราคาสาธารณะ) ต้องตั้งเองครั้งแรกที่สแกน
- นี่คือระบบสาธิต/ใช้งานจริงขนาดเล็กได้ ไม่มีระบบพิมพ์ใบเสร็จกระดาษ, ไม่มีระบบสต๊อกสินค้า,
  ไม่มีระบบผู้ใช้/สิทธิ์พนักงานหลายคน — แจ้งได้หากต้องการต่อยอดฟีเจอร์เหล่านี้
